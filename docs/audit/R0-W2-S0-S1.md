## W2-S1 — at-rest encryption READER, inert (commit `1877b2f`)
The decrypt-reader half of the engine, shipped BEFORE any writer (reader-first ⇒ every later step reversible).
Contract E1+E2+E4 (`storage-core.js`) + E7 (`sqlite-store.js`).
- **E1:** `STORAGE_ENCRYPT_ENABLED=false` (WRITES-only gate; `__FORCE_STORAGE_ENCRYPT` test override), `KEY_FILE
  'bcc.key'`, `ENV_MAGIC` "SBCC1", SQLite magic.
- **E2:** `subtleOK`/`isEnvelope`/`isSqlite`; memoized `loadKey`; `encryptForPersist` (wired in W2-S2 — DEAD here);
  `decryptIfEnveloped` (reader, always active; self-contained never-throw after the S-2 fold).
- **E4:** `rd()` now sniffs+decrypts per file — plaintext passes through byte-identical, an SBCC1 envelope decrypts,
  anything undecryptable → `null` → the existing live/.tmp/.bak/fresh recovery chain. `open()`'s `PRAGMA quick_check`
  stays the sole gate into MEM ⇒ ciphertext can never enter MEM.
- **E7:** sqlite-store stands down (no db-open, no write-through, `save()` never fires) if it ever sees an SBCC1 file
  — closes the flag-off rollback clobber vector (the byte[1] `0x42` magic can't false-positive a real SQLite header `0x51`).

**INERT by construction:** flag false + `encryptForPersist` has zero callers ⇒ `loadKey(true)` unreachable ⇒ **`bcc.key`
is never created, no file is written/created/deleted, production behavior byte-identical.** Fail-open reader: never
throws out of boot, never fail-closes plaintext.

3. **Harness** — engine `ready`, `lastError: none`, seeded data readable, DSR module opens, S0 probe still PASS,

4. **Adversarial** — 5 engine-focused skeptics (reader-regression, fail-open, E7-standdown, inertness, boot-recovery)

   `_keyP` sticky-null memoization (reader `loadKey(false)` caching null could block a live writer from minting a key);
