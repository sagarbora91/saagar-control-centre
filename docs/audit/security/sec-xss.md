# sec-xss — security audit

**Target:** shell + all modules
**Findings:** 4

**Coverage notes:** Audited all 11 extracted modules + shell www/index.html for stored-XSS via string-concat HTML. Method: grepped every innerHTML/insertAdjacentHTML/outerHTML/document.write sink and template-literal HTML builder, then traced whether interpolated values are user-controlled stored strings and whether they pass esc()/escapeHtml(). SAFE BASELINES (all user strings escaped — no gaps): service.html (escapeHtml on custName/brand/model/diagnosis/lineItems/followups, print via E=escapeHtml), stock.html (esc on brand/CRO names), payroll.html (escA/escT/slipEsc on name/empId/remarks/bank/slip), leave.html (pure DOM createElement+textContent for all names/reasons/agenda), dsr.html (esc on customer/product/billNo/remarks/staffName across all tabs + audit view), expense.html (esc on vendor/description/note/party/mobile — note e.source at line 925 is unescaped but is a system enum, not user text), qms.html (esc on name/mobile/note/croName/queueNo/visitType/preclaim across queueCard/rotation/preclaim), planning.html (esc on festival name/note/checklist), and shell index.html (escapeHtml/waEsc consistently — Customer 360 line 3266-3294, employee master 4922-4924, detected-names import 5037-5039, org tables 2651, masters 2802, sync 2714-2719, WA recipients 4568). The shell — which aggregates cross-module data and is the prime imported-backup target — is well-hardened. GAPS: 3 modules render stored user strings to innerHTML WITHOUT escaping. All 3 modules' localStorage data is included in the shell's backup/migration export payload (MIGRATION_KEYS lines 1925-1934: grooming prefix saagar_grooming_, cro_audit exact cro_audits_v3, tax exact taxcal_v2), so a crafted name/remark/firm-name in an imported file executes on another device's Android WebView — the exact cross-device path in the brief. Confidence high: sinks confirmed unescaped, sources confirmed free-text inputs, export path confirmed. Notably cro_audit and tax both DEFINE and USE their escapers elsewhere (stEsc in cro_audit print at 1698-1716; escapeHtml in tax Action Center/calendar/dashboard) but omit them on specific renders — a fix is low-risk (helper already present). grooming has NO escaper and needs one added. HARD RULES respected: fixes are additive, no new libs, no storage-core/sqlite-store/photo-store edits.

## [P0] xss-cro-audit-history — Stored XSS in CRO Audit: CRO/SM/store names + remarks rendered unescaped to innerHTML (history, modal, dashboards, textarea)
- **Module/area:** cro_audit | **Confidence:** high
- **Location:** extracted/cro_audit.html — renderHistory() line 1357; showModal() lines 1292-1294 & 1307-1309; renderWeekDash croHtml line 1475; renderCard textarea line 890 (sink: el.innerHTML / m-body.innerHTML)
- **Defect:** a.cro, a.sm, a.store and per-task td.remarks (all free-text: #f-cro 'full name' input line 1537, #f-sm line 1542, td.remarks <textarea> line 890) are interpolated raw into innerHTML with no escaping. renderHistory line 1357: `<div class="hi-cro">${a.cro}</div><div class="hi-store">${a.store} · SM: ${a.sm}</div>`. showModal line 1294 renders detail (which includes `"${td.remarks}"` from line 1292) and lines 1307-1309 render store/cro/sm raw. Dashboard cards line 1475 render CRO name `${nm}` raw. The remarks textarea line 890 (`${tData[t.id]?.remarks||''}`) lets a `</textarea><img src=x onerror=..>` payload break out. The file DEFINES stEsc (line 1686) and uses it correctly in printAudit (1709-1716) — the screen renders simply omit it.
- **Impact:** A CRO/SM name or audit remark like `<img src=x onerror=alert(document.cookie)>` saved on one device is exported via cro_audits_v3 (migration payload line 1933) and, when imported on another device, executes arbitrary JS in that WebView the moment the history list / audit modal / dashboard renders. Full stored, cross-device XSS: can read/rewrite all localStorage (money figures, ledgers, payroll), exfiltrate data, or corrupt records — script runs with the app's full origin privileges.
- **Fix hint:** Wrap every interpolated user value in the existing stEsc(): line 1357 -> ${stEsc(a.cro)}, ${stEsc(a.store)}, ${stEsc(a.sm)}; showModal 1292 -> `\"${stEsc(td.remarks)}\"`, 1293-1294 t.title/detail -> stEsc, 1307-1309 -> stEsc(a.store/a.cro/a.sm); dashboard cpc-name 1475 -> ${stEsc(nm)}; textarea 890 -> ${stEsc(tData[t.id]?.remarks||'')}. Additive, helper already exists, no new libs.

## [P0] xss-grooming-names — Stored XSS in Grooming: CRO name rendered unescaped to innerHTML in daily cards and leaderboard
- **Module/area:** grooming | **Confidence:** high
- **Location:** extracted/grooming.html — renderDaily() card.innerHTML line 809; renderLeaderboard() tr.innerHTML line 922 (also avatar initials 807/920)
- **Defect:** rec.name / c.name (CRO name, free text sourced from #cro-inp -> #cl-nm, backed by the user-editable CRO master) is interpolated raw: line 809 `<div class="cro-info-name">${rec.name}</div>` and line 922 `<div ...>${c.name}</div>`. grooming.html has NO escape helper defined anywhere — every render of the name is unescaped. (The i.label chips at 796 are hardcoded checklist labels, safe.)
- **Impact:** A CRO name containing an HTML/script payload, saved into a grooming record and exported via the saagar_grooming_ prefix (migration payload line 1927), executes on import when the daily view or monthly leaderboard renders on another device's WebView — stored cross-device XSS with full origin access (localStorage exfiltration/tampering across every module).
- **Fix hint:** Add a small escaper (e.g. function esc(s){return String(s==null?'':s).replace(/[&<>\"']/g,c=>({'&':'&amp;','<':'&lt;','>':'&gt;','\"':'&quot;',\"'\":'&#39;'}[c]));}) and wrap ${rec.name}->${esc(rec.name)} (809) and ${c.name}->${esc(c.name)} (922). Initials at 807/920 derive from name but are alnum-only after .slice; still safe to esc. Additive, no new libs.

## [P1] xss-tax-firm-list — Stored XSS in Tax: firm name/entity/PAN/GSTIN rendered unescaped in Firms list
- **Module/area:** tax | **Confidence:** high
- **Location:** extracted/tax.html — renderFirms() el.innerHTML lines 2005-2006
- **Defect:** f.name, f.entity, f.pan, f.gstin (all free-text firm inputs — #ff-name .value.trim() line 2024, etc.) are interpolated raw: line 2005 `<div class="firm-name">${f.name}</div>` and line 2006 firm-detail concatenates ${f.entity}, ${f.pan}, ${f.gstin} unescaped. escapeHtml IS defined (line 2839) and correctly used elsewhere in this same file (Action Center line 2679 ${escapeHtml(r.firm)}, calendar line 2973 ${escapeHtml(f.name)}, dashboard line 3021, firm selector uses DOM textContent line 2395) — so this single render just missed the helper.
- **Impact:** A firm name/PAN with a script payload saved on one device is exported via taxcal_v2 (migration payload line 1930); on import it executes when the Firms settings list renders on another device. Rated P1 rather than P0 because the firm master is typically edited only by the owner/admin (lower exposure than staff-entered CRO names/remarks), but the imported-backup cross-device path still makes it a real stored-XSS breach.
- **Fix hint:** Wrap with the file's existing escapeHtml: line 2005 -> ${escapeHtml(f.name)}; line 2006 -> ${escapeHtml(f.entity||'')}, ...'+escapeHtml(f.pan), ...'+escapeHtml(f.gstin). Additive, helper already present.

## [P3] xss-cro-audit-datalist-lowrisk — CRO name in cro_audit datalist option value escapes only quotes (not <>) — low risk / note
- **Module/area:** cro_audit | **Confidence:** medium
- **Location:** extracted/cro_audit.html — refreshCroDatalist() dl.innerHTML line 1846-1847
- **Defect:** CRO master names go into `<option value="'+n.replace(/\"/g,'&quot;')+'">` — only the double-quote is escaped, not < or >. Because the value sits inside a double-quoted attribute of a void-ish <option> with no closing text node, a payload cannot break out of the attribute to inject a tag (quotes are neutralised), so this is not directly exploitable. Noted for completeness as an inconsistent-escaping spot; the primary CRO-name XSS is finding xss-cro-audit-history.
- **Impact:** No practical script execution on its own (attribute-only context with quotes escaped). Defense-in-depth gap only.
- **Fix hint:** For consistency, run the value through stEsc() instead of the partial quote-only replace: value=\"'+stEsc(n)+'\". Optional / low priority.
