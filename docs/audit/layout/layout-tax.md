# layout-tax — layout audit

**Target:** tax.html
**Findings:** 9

**Coverage notes:** Method: read full tax.html (CSS + all render fns) and INJECTION_PIPELINE.md. Screens covered: Control Calendar (compliance cards .cc with control-strip pills, done-capture row, Controls accordion containing .owner-grid/.cos-grid/.ng/checklist/workflow/penalty), COS Dashboard (.dash-stats 4-col, .dash-grid-2, .focus-row tables, ops-list, nc-section), Firms modal (.ff-grid/.firm-row), Manage Compliance modal (.ff-grid + nested control .ff-grid + textareas), Action Center modal (.ac-sum/.ac-row), category filter, view-tabs, month-nav, stats KPI row, new-Act form renumbering (renderNewActForms at :1002 — text-only transform, no layout impact; no invented section numbers, verified it only rewrites existing baked strings).

Key architecture finding that DOWNGRADES most grid risk: this module's responsiveness is driven ENTIRELY by its OWN width-based @media queries (600/640/860px), which fire independently of the bcc-mobile class. Therefore at real phone widths 360x740 and 412x915 — in BOTH Mobile AND Desktop display — every multi-column grid (dash-stats→2col, cos-grid/owner-grid/dash-grid-2/focus-row/ff-grid/ng→1col) DOES collapse. The only off-combo where grids stay multi-column is 1280xMobile (Mobile display forced on a wide viewport), where multi-column is visually fine. So there is NO 'grid stuck multi-column at 360' failure here (unlike modules that rely on bcc-mobile scoping). All modals (.modal, firm/master/action-center) have max-height:90vh;overflow-y:auto (:280) so footers/action buttons are always reachable — no P0 modal-clip. Tables: the only real table is the PRINT preview (stp-table) which is rendered by the SHELL, not in-iframe, so out of scope; in-app 'tables' are CSS grids, not <table>, so the base table{display:block;overflow-x:auto} rule is moot here.

The single most impactful real-device issue is tax-01 (done-capture inline row not stacking in Mobile display until ≤600px, so on 1280xMobile and the 601-640 window the filing form is a dense wrapping row of 44px controls with mis-associated labels). Everything else is P2/P3 polish.

Could NOT verify statically (needs live browser / device): (1) exact pixel height of the wrapped .hd sticky header on a 360 device and how much viewport it steals (tax-04); (2) whether the native file-input control actually exceeds its container at 16px on the Android WebView (tax-08); (3) real-device tap behaviour of the horizontally-scrolling month-nav with the injected shell back/home FAB — whether the FAB overlaps the bottom-most compliance card (shell FAB is injected outside this file, not visible here); (4) whether the shell injects a per-module bcc-mobile[data-mod=tax] block (the pipeline doc lists 'tax' among per-module overrides but does not spell out its contents) — if that block already stacks .done-capture-row, tax-01 is mitigated; this must be confirmed against the shell's actual MOBILE_CSS string. Recommend live-loading tax in the iframe at 360xMobile, 412xMobile, 1280xDesktop, and forced 1280xMobile to confirm tax-01/tax-04.

## [P1] tax-01 — Compliance-card done-capture row: 5 labels + 4 text/date inputs + file input on ONE flex row, all forced to 44px height / 16px font by the shell floor
- **Module/area:** tax | **Confidence:** high | **Combo:** 1280xMobile, 412xMobile (601-640 window), 1280xDesktop
- **Location:** tax.html:189 (.done-capture-row) + render at :2983 (the .done-capture markup) ; collapse rule only at :380 @media(max-width:600px)
- **Defect:** .done-capture-row is display:flex;flex-wrap:wrap holding 5 <label>s, 4 text/date <input>s, one file <input class=ev-file-inp>, and Confirm/Cancel buttons. The module only turns it into a single-column grid at @media(max-width:600px) (:380). The shell's uniform-CSS control floor forces every input to min-height:44px !important + font-size:16px, and .done-capture input rules at :569 also force min-height:44px;font-size:16px. In Mobile display on a WIDE viewport (1280xMobile, bcc-mobile ON but width>640 so no collapse fires) and in Desktop on viewports 601-640px, this stays a single dense wrapping row of ten+ tall 44px controls with tiny 11px labels crammed between them, wrapping unpredictably. The date/text inputs are only min-width:120px (:192) so several fit per line and the label→input association is visually lost.
- **Evidence:** .done-capture-row{display:flex;align-items:center;gap:8px;flex-wrap:wrap;} + shell floor input{min-height:44px!important;font-size:16px} ; single-col collapse gated at @media(max-width:600px){.done-capture-row{grid-template-columns:1fr}}
- **Impact:** The 'mark filed' capture form — the core write action of the module — becomes a jumbled wall of tall inputs whose labels no longer line up with their fields, on the exact wide-Mobile combo the shell can produce. Error-prone data entry for filing date / ack no. / evidence ref.
- **Fix hint:** Add a bcc-mobile per-module rule (html.bcc-mobile[data-mod=tax] .done-capture-row{display:grid;grid-template-columns:1fr}) so it stacks in Mobile display regardless of width, matching how the module already stacks it at ≤600px. Do not touch storage-core.

## [P2] tax-02 — Multi-column grids (dash-stats/cos-grid/owner-grid/dash-grid-2/focus-row/ff-grid/ng) do NOT collapse in Mobile display at wide widths — they only collapse via the module's own width @media (600/640/860px)
- **Module/area:** tax | **Confidence:** high | **Combo:** 1280xMobile
- **Location:** tax.html:224 (.dash-stats 4-col), :404 (.cos-grid 3-col), :409 (.owner-grid 2-col), :429 (.dash-grid-2 2-col), :437 (.focus-row 4-col), :297 (.ff-grid 2-col), :179 (.ng 2-col) — all collapse ONLY inside @media(max-width:860/640/600)
- **Defect:** Every collapse-to-1-column rule for these grids lives in the module's own width-based @media queries (:343 600px, :441 860px, :457 640px). None is scoped under html.bcc-mobile. So in the 1280xMobile off-combo (Mobile display on a wide viewport) NONE of the width queries fire and every grid stays multi-column. On a genuinely wide viewport that is acceptable (the columns fit), so this is not the 360 failure — at 360xMobile and 360xDesktop the width queries DO fire and everything collapses correctly. Flagging as the structural risk item: the module has no bcc-mobile-scoped collapse, so responsiveness is width-driven only.
- **Evidence:** @media(max-width:640px){.cos-grid{grid-template-columns:1fr}.dash-grid-2{grid-template-columns:1fr}.owner-grid{grid-template-columns:1fr}.ff-grid{grid-template-columns:1fr}.ng{grid-template-columns:1fr}.focus-row{grid-template-columns:1fr}.dash-stats{grid-template-columns:repeat(2,1fr)}} — all width-gated, zero bcc-mobile scoping
- **Impact:** No functional break at real phone widths (360/412) because the width queries fire there too. Only cosmetic on the artificial wide-Mobile combo. Documented so a future MOBILE_CSS change that relies on bcc-mobile scoping (not width) won't be assumed present here.
- **Fix hint:** No fix required for device widths; if uniformity with other modules is wanted, mirror the collapses under html.bcc-mobile[data-mod=tax]. Leave as-is is defensible.

## [P2] tax-03 — .control-strip risk/cashflow/escalation pills + long 'Internal due <date>' pill can overflow the narrow cc-left column on 360
- **Module/area:** tax | **Confidence:** medium | **Combo:** 360xMobile, 360xDesktop
- **Location:** tax.html:413 (.control-strip flex-wrap) + :414 (.control-pill) ; rendered at :2983 with 4 pills incl 'Internal due 28 Feb'
- **Defect:** Each compliance card renders a .control-strip with 4 .control-pills: '<Risk> Risk', '<level> Cash Flow', an escalation label, and 'Internal due <shortdate>'. control-strip is flex-wrap:wrap so pills wrap, but at 360 (after .cc-top goes column at :374 and cc-right stretches) the cc-left content column is ~300px. The shell text floor forces .control-pill to font-size:11px (from :547-552 list) overriding the module's 9px, so pills are physically larger than designed and wrap to 3-4 rows. control-pill has letter-spacing:.05em;text-transform:uppercase;white-space not set — a pill like 'INTERNAL DUE 28 FEB' stays one token line but occupies most of the row width.
- **Evidence:** .control-strip{display:flex;gap:6px;flex-wrap:wrap} .control-pill{font-size:9px;...text-transform:uppercase} overridden to font-size:11px by the normalization floor list at :547-552
- **Impact:** Cards become tall on phones (4 pills stacking to multiple rows), pushing the Controls/done button further down; visually noisy but not broken (wrap prevents horizontal overflow).
- **Fix hint:** Acceptable; if tightening desired, reduce control-strip gap or allow the internal-due pill to abbreviate under html.bcc-mobile[data-mod=tax]. No storage change.

## [P2] tax-04 — Header (.hd) is sticky top:0 z-index:200 and wraps to a tall 2-3 row grid on phones, consuming a large slice of viewport above the non-sticky view-tabs/month-nav
- **Module/area:** tax | **Confidence:** medium | **Combo:** 360xMobile, 412xMobile, 360xDesktop
- **Location:** tax.html:38 (.hd sticky) ; :353 (.hd-right becomes 2-col grid at ≤600px) ; .view-tabs :58 and .mnav :64 are NOT sticky
- **Defect:** In @media(max-width:600px) the header restacks: hd-right becomes a 2-col grid of 5 full-width buttons (Action Center, Firms, Manage Compliance, CSV, Print) plus two full-width firm/FY selects, so .hd becomes ~5-6 rows tall. Because .hd is position:sticky;top:0, that entire tall block stays pinned while scrolling, eating a large fraction of a 740px phone viewport. The shell also injects its own back/home chrome and body{padding-bottom} — the module header does not account for shell chrome, but since it's inside the iframe the sticky is scoped to the iframe so it does not overlap shell chrome (no double-stack), it just wastes vertical space.
- **Evidence:** .hd{...position:sticky;top:0;z-index:200} + @media(max-width:600px){.hd-right{width:100%;display:grid;grid-template-columns:1fr 1fr}.btn-hd{width:100%}.firm-sel{width:100%}}
- **Impact:** On a 360x740 phone the pinned header can occupy 30-40% of the visible height, leaving little room for compliance cards; usable but cramped. Not an overlap/clip failure.
- **Fix hint:** Consider dropping position:sticky on .hd under html.bcc-mobile[data-mod=tax] (let it scroll away on phones) so cards get full height. Cosmetic; verify on device.

## [P3] tax-05 — View-tabs and month-nav are horizontally scrollable but the 44px tab-height floor + font floor thicken them, and they are not pinned — scrolling reveals cards under a non-sticky nav
