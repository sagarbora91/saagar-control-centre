## [P1] leave-01 — Day-modal pending leave row overflows: avatar + 2 badges + three 44px action buttons in a no-wrap flex row
- **Module/area:** leave | **Confidence:** high | **Combo:** 360xMobile
- **Location:** leave.html .leave-row (CSS line 225) built in openDayModal() JS lines 1536-1573; approve/reject/delete buttons use class .leave-row-del (lines 1560-1571)
- **Defect:** A pending leave row in the Day modal renders, in order: .leave-avatar (33px, flex-shrink:0) + .leave-row-info (flex:1,min-width:0) + type .leave-row-badge + status .leave-row-badge ('pending') + three .leave-row-del buttons (approve ✓, reject ⊘, delete ×). .leave-row is `display:flex;align-items:center;gap:10px` with NO flex-wrap (line 225). The uniform control floor forces every .leave-row-del to `min-height:44px !important; min-width:44px` (matched by `button[class*="-del"]`, _uni.css lines 68-78). Three 44px buttons + 10px gaps need ~152px; add 33px avatar, two badges (each ~50-60px, white-space:nowrap line 235) and the flexible info column is squeezed toward 0. At 360px the row content exceeds the modal width; because .modal has overflow-y:auto (line 186) its overflow-x computes to auto, so the day modal gains an awkward horizontal scrollbar and the leave name/meta becomes unreadable.
- **Evidence:** .leave-row { ... display: flex; align-items: center; gap: 10px; } (line 225, no flex-wrap) + JS row.appendChild(av); appendChild(info); appendChild(badge); [pending] appendChild(ok); appendChild(no); appendChild(del); (lines 1550-1572) + _uni.css `html body button[class*="-del"]{min-height:44px !important;min-width:44px}`
- **Impact:** On a phone, the primary approve/reject/delete workflow row for a pending leave overflows horizontally; name+meta collapse and the modal scrolls sideways. Core approval flow is degraded though still operable via the separate Approvals modal.
- **Fix hint:** Add a leave-specific mobile rule in the shell block (html.bcc-mobile[data-mod="leave"] .leave-row{flex-wrap:wrap;row-gap:8px}) OR add `.leave-row{flex-wrap:wrap}` to the module's @media(max-width:640px). Optionally let the action buttons form a full-width wrapped row (flex-basis). No JS/storage change.

## [P2] leave-02 — Tiny 26px row-action buttons (.leave-row-del/.emp-del/.agenda-del) inflated to 44x44 on Desktop by the unconditional control floor
- **Module/area:** leave | **Confidence:** high | **Combo:** 1280xDesktop
- **Location:** leave.html .leave-row-del (line 247, 26x26), .emp-del (line 300, 26x26), .agenda-del (line 262, ~13px inline), .modal-close (line 199, 30x30), .nav-btn small Add buttons (day modal, inline font-size:11px)
- **Defect:** The uniform control floor (`min-height:44px !important; min-width:44px`, _uni.css lines 68-78) is injected UNCONDITIONALLY (both modes). It matches .leave-row-del/.emp-del/.agenda-del via `button[class*="-del"]`, and .modal-close / .btn via their selectors. The module only compensates at mobile widths (@media(max-width:640px) lines 431-432 give these 44px). On DESKTOP (>640px, bcc-mobile OFF) these deliberately-compact 26-30px icon buttons and the inline `font-size:11px;padding:5px 10px` '＋ Add' section buttons all become 44x44, distorting the dense day-modal leave rows, the emp-master rows, and forcing every .section-head to 44px tall. Not broken, but visibly oversized vs the intended compact design.
- **Evidence:** .leave-row-del { width:26px; height:26px; ... } (line 247); .emp-del { width:26px;height:26px } (line 300); floor `html body button[class*="-del"]{min-height:44px !important;min-width:44px}` applies with no bcc-mobile gate
- **Impact:** Cosmetic distortion of dense action clusters on desktop/tablet; rows are taller and buttons larger than designed. Fully usable.
- **Fix hint:** Accepted trade-off of the global accessibility floor; if undesired on desktop, scope the module's compact sizing with higher specificity or accept 44px as the a11y minimum. Do NOT weaken the floor. No storage change.

## [P2] leave-03 — Phone agenda-reflow day cards forced to 92px min-height by shell rule overriding the module's intended 44px, over-inflating single-chip cards
- **Module/area:** leave | **Confidence:** high | **Combo:** 360xMobile
- **Location:** shell index.html:6343 `html.bcc-mobile[data-mod="leave"] .cal-cell{min-height:92px;padding:6px 5px}` vs leave.html @media(max-width:599px) .cal-cell{min-height:44px;padding:11px 14px} (lines 461-469)
- **Defect:** At 360/412 Mobile the module's @media(max-width:599px) reflows .cal-grid to a vertical agenda list where each day-card is meant to be a compact `min-height:44px` tap target (line 462). But the shell's per-module rule `html.bcc-mobile[data-mod="leave"] .cal-cell{min-height:92px}` (specificity 0,3,1, injected AFTER module CSS) beats the module's `.cal-cell` inside @media (specificity 0,1,0). So every reflowed day-card is forced to a 92px-tall box even when it holds one short chip, and the shell's `padding:6px 5px` overrides the reflow's intended `padding:11px 14px`. Result: over-tall, tightly-padded agenda cards and more scrolling than designed. The reflow still functions.
- **Evidence:** shell:6343 min-height:92px (bcc-mobile[data-mod=leave] .cal-cell) wins over module @media599 .cal-cell{min-height:44px} on specificity; the 92px rule was authored for the 7-col grid, not the <599 agenda reflow which the shell author did not account for
- **Impact:** Wasted vertical space / extra scrolling in the phone agenda list; purely spatial, no data loss.
- **Fix hint:** Add `html.bcc-mobile[data-mod="leave"] .cal-grid{...}` guard OR wrap the shell's cal-cell sizing in `@media(min-width:600px)` so it only applies to the grid layout, letting the module's <599 reflow (44px) take over on phones. No JS/storage change.

## [P2] leave-05 — Report modal table sticky first-column combined with base-mobile `table{display:block}` may break the pinned Employee column
- **Module/area:** leave | **Confidence:** low | **Combo:** 360xMobile
- **Location:** leave.html .report-table th/td:first-child{position:sticky;left:0} (lines 313-318); table built in openReport() JS lines 2133-2184 inside a div with inline overflowX:auto; base mobile rule shell:6180-6181
- **Defect:** The report table pins the Employee column via `position:sticky;left:0` on td/th:first-child. In Mobile the shell base rule `html.bcc-mobile table{display:block;overflow-x:auto}` plus `thead,tbody,tr{width:max-content;min-width:100%}` changes the table's formatting context. sticky left within a `display:block` table whose rows are `width:max-content` frequently mis-behaves (the sticky cell can detach from its row or fail to pin) across WebView versions. The module already double-wraps the table in an overflowX:auto div and sets .report-table{min-width:520px} at <=640, so it will still scroll, but the sticky identity column — the whole point of a 8-column wide report on a phone — may not stay pinned. Needs live device confirmation.
- **Evidence:** .report-table th:first-child, td:first-child { position: sticky; left: 0; z-index: 1; ... } (lines 314-315) interacting with `html.bcc-mobile table{display:block}` (shell:6180) + `tr{width:max-content}` (shell:6181)
- **Impact:** If sticky fails, the Employee name scrolls away while reading Full/Half/Balance columns on a phone, hurting the 8-col report's readability. Table still scrolls, no data loss.
- **Fix hint:** Verify on-device; if sticky drops, either keep the table as a real table on mobile for this module (html.bcc-mobile[data-mod="leave"] .report-table{display:table} inside its scroll wrapper) or drop sticky on mobile and rely on horizontal scroll. No storage change.

## [P3] leave-07 — leave-chip font-size fought over by three layers; uniform 11px floor wins, defeating the reflow's intended 12px readable chips
- **Module/area:** leave | **Confidence:** high | **Combo:** 360xMobile
- **Location:** leave.html @media(max-width:599px) .leave-chip{font-size:12px} (line 488); shell:6344 .leave-chip{font-size:9.5px}; _uni.css:54-62 hard floor `html body .leave-chip{font-size:max(11px,1em)!important}`
- **Defect:** Three rules target the phone chip size: module reflow wants 12px (line 488) for readability; shell leave block sets 9.5px (line 6344); the uniform hard floor sets max(11px,1em)!important (matches `html body .leave-chip`). The !important floor beats both non-important rules, so chips render at exactly 11px in the agenda list — not the 12px the reflow author intended for phone legibility, and thankfully not the shell's sub-floor 9.5px. Net effect is a slightly smaller-than-intended chip; benign because 11px meets the a11y floor. Documents that the shell's 9.5px rule (6344) is dead code (always overridden by the floor).
- **Evidence:** line 488 font-size:12px vs shell:6344 font-size:9.5px vs _uni.css `html body .leave-chip{font-size:max(11px,1em)!important}` — the !important floor wins → 11px
- **Impact:** Chips 1px smaller than the reflow's target; no functional impact. The shell's 9.5px rule never takes effect.
- **Fix hint:** None required (11px is the intended accessibility minimum). Optionally remove the dead 9.5px rule at shell:6344 to avoid confusion. No storage change.
