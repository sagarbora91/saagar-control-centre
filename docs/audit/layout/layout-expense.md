## [P2] expense-L1 — KPI tile values have no wrap/ellipsis — long ₹ (crore) amounts or long top-expense-head text overflow the 2-up mobile tile
- **Module/area:** expense | **Confidence:** medium | **Combo:** 360xMobile, 412xMobile
- **Location:** expense.html CSS `.kpi .v` (line 73) + `.kgrid` forced to `repeat(2,1fr)` on mobile (module @media line 195 and shell `html.bcc-mobile[data-mod="expense"] .kgrid` index.html:6273); rendered by kpi() line 638 and renderDash/renderPetty/renderClose
- **Defect:** `.kpi .v{font-size:22px;font-weight:700;font-family:var(--font-serif)}` (mobile 19px) sets no `overflow`, `white-space`, `word-break`, or `text-overflow`. The KPI grid is forced to 2 columns at every mobile width including 360px, giving each tile only ~137px of inner content width. A long numeric like nINR of a crore figure (`₹1,23,45,678`, ~12 chars) has no break opportunities (thousands separators are commas, no spaces) and cannot wrap, so it overflows the tile horizontally. The 'Top expense head' KPI (renderDash line 627) and Petty 'Status' value hold arbitrary text that is also unbounded.
- **Evidence:** .kpi .v{font-size:22px;font-weight:700;color:var(--navy);margin:6px 0 2px;font-variant-numeric:tabular-nums;font-family:var(--font-serif)}  /* no overflow/word-break; .kgrid{grid-template-columns:repeat(2,1fr)} at ≤640 */
- **Impact:** On 360×Mobile / 412×Mobile, large-value KPI numbers (Cash in hand, Month P&L, Disbursed) can bleed past the tile edge or push tile width, producing a ragged/overflowing dashboard for high-turnover days. Data is still legible but visually broken.
- **Fix hint:** Add to `.kpi .v` (and `.kpi .l`,`.kpi .s`): `min-width:0;overflow-wrap:anywhere` or `overflow:hidden;text-overflow:ellipsis` with `white-space:nowrap` for numeric tiles; module-CSS only, no storage/library change.

## [P2] expense-L2 — Denomination-row total column is a fixed 90px grid track on Desktop — long cash totals (₹40,00,000) overflow the track into the gap
- **Module/area:** expense | **Confidence:** medium | **Combo:** 1280xDesktop, 360xDesktop
- **Location:** expense.html `.deno-row{grid-template-columns:60px 1fr 90px}` (line 137); value span rendered in denoBox() line 930 (`<span class="num">'+nINR(num(...)*v)+'</span>`)
- **Defect:** On Desktop display the third grid track is a hard `90px`. The span holds `nINR(count × denomination)`; for the ₹2000 or ₹500 rows a realistic branch count (e.g. 2000 notes × ₹2000 = ₹40,00,000, or even ₹5,00,000) renders a string wider than 90px. A fixed grid track does not grow, so the text overflows its cell and collides with the input to its left / spills past the box. Mobile is safe (shell rewrites the track to `48px 1fr auto`, index.html:6274), so this is Desktop-only.
- **Evidence:** .deno-row{display:grid;grid-template-columns:60px 1fr 90px;gap:6px;align-items:center;font-size:12px}
- **Impact:** In the Cash Statement deno boxes (Physical cash counted / Deposited to bank) on 1280×Desktop, high-denomination totals visually overflow/overlap. Non-fatal — counting still works — but the reconciliation grid looks broken for large cash days.
- **Fix hint:** Change desktop track to `minmax(90px,auto)` (or `auto`) for the third column of `.deno-row`, matching the mobile `auto`; add `white-space:nowrap;text-align:right` to `.deno-row .num`. Module CSS only.

## [P2] expense-L3 — Vendor/Budget/etc. card-reflow is gated on width (@media 640px) not on bcc-mobile — in Mobile mode on a wide viewport (1280×Mobile) these list tables never become cards
- **Module/area:** expense | **Confidence:** medium | **Combo:** 1280xMobile
- **Location:** expense.html card-reflow block `@media(max-width:640px){ .gm-tbl-vendors/.gm-tbl-budget/.gm-tbl-monthsum/.gm-tbl-firmpl … }` (lines 252-306); shell base rule `html.bcc-mobile table{display:block;overflow-x:auto}` index.html:6180
- **Defect:** The intended mobile presentation of the Vendors, Budgets, Month-summary and Per-firm P&L tables is the stacked-card reflow, but that reflow lives entirely inside the module's own `@media(max-width:640px)` — a viewport-width query. It is NOT scoped under `html.bcc-mobile`. When the shell is in Mobile display at a wide width (the documented 1280×Mobile off-combo, e.g. a tablet/foldable/desktop with Mobile mode selected), the width query does not fire, so these tables fall back to the shell base `display:block;overflow-x:auto` scroll-table instead of cards. Functionally usable but inconsistent with the module's mobile intent, and the per-table `data-label`/name-cell styling is dead in that combo.
- **Evidence:** @media(max-width:640px){ .gm-tbl-vendors{min-width:0!important;width:100%;display:block} .gm-tbl-vendors thead,.gm-tbl-vendors tfoot{display:none} … }  /* width-gated, not under html.bcc-mobile */
- **Impact:** Cosmetic/consistency: on Mobile-mode wide screens the vendor/budget/firm tables render as plain scroll tables rather than the designed cards. No data loss, no blocked flow.
- **Fix hint:** Either add `html.bcc-mobile[data-mod="expense"] .gm-tbl-vendors{…}` mirrors in the shell MOBILE_CSS, or accept width-gating as sufficient (360/412 real phones fire the media query). Low priority; note it needs live confirmation of whether 1280×Mobile is a real device target.

## [P2] expense-L4 — Card-reflow rows can widen: shell `tr{width:max-content}` applies to the module's display:block reflowed rows (360×Mobile)
- **Module/area:** expense | **Confidence:** low | **Combo:** 360xMobile
- **Location:** shell `html.bcc-mobile thead,tbody,tr{width:max-content;min-width:100%}` (index.html:6181) vs module `.gm-tbl-vendors tbody tr{display:block …}` (line 256, sets no width)
- **Defect:** At 360×Mobile both layers are active. The module reflows `.gm-tbl-*` rows to `display:block` cards but never sets a width on the `tr`. The shell base rule `html.bcc-mobile … tr{width:max-content;min-width:100%}` (element-level, low specificity but not overridden for width) leaves `width:max-content` on those block rows. A `display:block` element with `width:max-content` sizes to its widest unbreakable content; the navy full-width `.name-cell` and right-aligned amount cells contain `min-width:0`/`flex` children so they usually collapse to 100%, but a long unbreakable vendor name or note (`esc(v.name)`) with no spaces could push `max-content` past 100% and cause the card (and page) to exceed 360px. Module sets `html,body{overflow-x:hidden}` at ≤640 which masks page-level overflow, but the card itself can still be clipped.
- **Evidence:** html.bcc-mobile thead,html.bcc-mobile tbody,html.bcc-mobile tr{width:max-content;min-width:100%}  ×  .gm-tbl-vendors tbody tr{display:block;margin:0 0 12px;…}  /* tr width unset */
- **Impact:** Edge case: a long single-token vendor/customer name in the reflowed Vendors/Budget cards on a 360px phone can make the card wider than the viewport (clipped by body overflow-x:hidden) rather than wrapping.
- **Fix hint:** In the module reflow blocks add `width:100%` (or `width:auto`) to `.gm-tbl-* tbody tr` to defeat the inherited `width:max-content`, and `overflow-wrap:anywhere` on `.name-cell`. Module CSS only. Needs live-browser confirmation of the max-content interaction.

## [P3] expense-L5 — Long customer name + mobile + note stacked in the Udhaar 'Who owes you' first cell — no wrap control; relies solely on horizontal scroll
- **Module/area:** expense | **Confidence:** low | **Combo:** 360xMobile, 412xMobile
- **Location:** renderUdhaar() outstanding table, first `<td>` (line 1290): `'<b>'+esc(r.name)+'</b>'+(r.mobile?'<br><span class="muted small">…':'')+(r.note?'<br>…')`; table has no gm-tbl class so stays a scroll table (min-width:760px at ≤640)
- **Defect:** The Udhaar receivables table is intentionally kept as a horizontal-scroll log (7 columns, `.twrap` with `.twrap table{min-width:760px}` on mobile, sticky first column). The identity cell stacks name/mobile/note via `<br>`. A long free-text `note` (e.g. 'Titan Raga, promised in 30 days after Diwali') has no `word-break`/`max-width`, so the sticky first column can grow very wide, and because it is `position:sticky;left:0` it overlays the scrolled columns when the user scrolls right, potentially covering the amount columns behind it.
- **Evidence:** '<td><b>'+esc(r.name)+'</b>'+(r.mobile?'<br><span class="muted small">'+esc(r.mobile)+'</span>':'')+(r.note?'<br><span class="muted small">'+esc(r.note)+'</span>':'')+'</td>'  /* .twrap th:first-child,td:first-child{position:sticky;left:0} */
- **Impact:** On phones, a verbose note widens the pinned identity column; when scrolling the 7-col table horizontally the wide sticky column can obscure adjacent Amount/Outstanding cells. Minor readability issue; data reachable by scrolling back.
- **Fix hint:** Cap the identity column: add `max-width:180px;overflow-wrap:anywhere` (or clamp the note with ellipsis) on the first `td` of the udhaar table; keep sticky. Module CSS only.

## [P3] expense-L6 — Ledger action cell packs up to 4 44px-floored buttons (Send/Approve/Edit/Void) in one td — very tall/wide action column
- **Module/area:** expense | **Confidence:** low | **Combo:** 360xMobile, 412xMobile
- **Location:** ledgerTable() action cell (lines 713-715); shell control floor `button/.btn{min-height:44px!important;min-width:44px}` (index.html:6141-6151, td relief only sets min-width:0)
- **Defect:** The non-compact Ledger action column can render four `.btn.xs` buttons (`↗ Send`, `Approve`, `Edit`, `Void`) in a single cell. Every one is forced to `min-height:44px !important` by the shell floor; `min-width:44px` is not !important and the td relief zeroes min-width, so they can shrink horizontally but each is 44px tall. Four buttons in one row cell inside a `min-width:760px` scroll table means the Action column is wide and the buttons stay on one line (they don't wrap in a td). Acceptable because the whole table scrolls, but the action column dominates and the row height is large.
- **Evidence:** (compact?'':'<td class="num"><button class="btn xs" …>↗ Send</button> '+(…?'<button class="btn xs green" …>Approve</button> ':'')+(… '<button class="btn xs" …>Edit</button> <button class="btn xs red" …>Void</button>'))
- **Impact:** Minor: dense/tall action column in the full Ledger tab on mobile; usable via horizontal scroll. Not blocking.
- **Fix hint:** Optional: in mobile, allow the ledger action td to wrap (`white-space:normal`) or shrink `.btn.xs` icon-only. Low priority; the 44px floor is an intentional accessibility rule and should not be lowered.

## [P3] expense-L7 — Statement/Vendors/Close inline-styled inputs use hardcoded padding and no explicit width — 44px control floor + 16px font can distort the compact date/month pickers
- **Module/area:** expense | **Confidence:** low | **Combo:** 1280xMobile, 360xMobile
- **Location:** inline inputs: cash-statement date `style="padding:7px 9px;…"` (line 827), Close month `<input type="month" style="padding:7px;…">` (line 1129), Vendor name `style="padding:9px 11px;…flex:1"` (line 1024), Budget input `style="width:100px;padding:5px"` (line 1047)
- **Defect:** These inline-styled inputs sit outside `.fld`. The shell floor forces `min-height:44px !important` and mobile `input{font-size:16px}`, overriding their compact `padding:5px/7px`. The Budget input's inline `width:100px` is overridden to `width:auto!important` inside the card-reflow (fine), but in the 1280×Mobile no-reflow combo it keeps 100px with 16px font and 44px height — a squat 100px×44px box that barely fits `₹1,00,000`. The month/date pickers in `.card-h .actions` (shell forces that strip to `overflow-x:auto;nowrap`) become 44px-tall 16px controls in a horizontal scroll strip.
- **Evidence:** '<input type="number" min="0" value="'+(bm[c]||'')+'" … style="width:100px;padding:5px;border:1px solid var(--gray-300);border-radius:6px;text-align:right" onchange="setBudget(...)">'
- **Impact:** Cosmetic: inline controls are taller/chunkier than designed and the 100px budget input is tight for 6-digit budgets in the non-reflow combo. No blocked flow.
- **Fix hint:** Widen the budget input (`min-width:120px`) and let it grow; these are acceptable given the intentional 44px/16px floors. Confirm on device.
