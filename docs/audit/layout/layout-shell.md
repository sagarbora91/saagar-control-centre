## [P2] shell-emp-pill-undefined — `.emp-pill` (and `.emp-pill.green/.amber`) has NO CSS definition — renders as unstyled colliding text on 6+ shell surfaces
- **Module/area:** shell | **Confidence:** high | **Combo:** all
- **Location:** index.html — CSS blocks lines 22-1099 (no `.emp-pill` rule exists); used by renderCustomer360() line 3287-3290, employee stats line 4905-4909, exportMigration summary line 5106-5108, restore review line 5260-5265, storage summary line 5618-5620, audit trail line 5672-5674
- **Defect:** The class `.emp-pill` is used to render KPI/stat pills across many shell screens but is never defined in any shell <style> block (all CSS is inline; there is no external stylesheet). Only `.emp-stat` and `.emp-badge` are defined. Each pill is `<div class="emp-pill"><b>VALUE</b><span>LABEL</span></div>`; with no rule, `<b>` is default inline-bold and `<span>` inline, so value and label collide on one line with no card background, border, padding or gap (e.g. `₹5,00,000Lifetime value`, `5Total`). The `.green`/`.amber` state variants (used on People stats and Customer 360 'In Payroll'/'In Leave') also do nothing, so the intended warning/OK colour signal is silently lost.
- **Evidence:** Grep for `\.emp-pill\s*\{` returns 'No matches found'; usages: `<div class="emp-pill"><b>${c360INR(d.ltv)}</b><span>Lifetime value</span></div>` (line 3287) and `<div class="emp-pill green"><b>${stats.active}</b><span>Active</span></div>` (line 4906).
- **Impact:** Every stat block on Customer lookup (Home), Settings→People stats, Settings→Data & backup (migration export summary, restore review, stored-data summary), and Diagnostics→Audit trail shows an unstyled run-together number+label with no card chrome and no green/amber status colour. On Customer 360 the pills sit in `.kpi-grid` (2 cols @360); a long ₹ LTV like `₹12,34,567` in a bold inline `<b>` with `+Lifetime value` has no min-width:0/ellipsis, so it can inflate the grid column and be clipped by `.main{overflow:hidden auto}`.
- **Fix hint:** Add a shell CSS rule for `.emp-pill` mirroring `.emp-stat` (white card: background:#fff;border:1px solid var(--gray-200);border-radius:10px;padding:10px;display:flex;flex-direction:column) with `.emp-pill b{font-family:var(--font-serif);font-size:22px;line-height:1.1}` and `.emp-pill span{font-size:10px;text-transform:uppercase;color:var(--gray-500)}`, plus `.emp-pill.green b{color:var(--green)}` / `.emp-pill.amber b{color:var(--amber)}`, and `min-width:0` on the pill so long ₹ values wrap instead of clipping. Additive CSS only.

## [P2] shell-row-btn-undefined-masters-sync — `.row`, `.btn.sm`, `.btn.p` undefined — Masters & Sync input rows are not flex, `gap`/`flex:1` ignored, inputs don't stretch
- **Module/area:** shell | **Confidence:** high | **Combo:** all
- **Location:** index.html — Settings→Masters markup lines 1354-1372 (`<div class="row" ...>` + `class="btn sm"` / `class="btn p"`), Settings→Sync module-settings render line 2746-2748 (`<div class="row" ...>` + `class="btn sm p"`)
- **Defect:** The Masters subtab (Brands / Vendors / Customers add-rows and the shortcut-button row) and the Sync subtab's per-module settings editor wrap controls in `class="row"`, but `.row` has no CSS definition (Grep `\.row\s*\{` = no match). The rows carry inline `style="gap:8px;flex-wrap:wrap"` and inputs carry `flex:1;min-width:140px`, but `gap` and `flex` only apply inside a flex/grid container. As a plain block, the container ignores `gap` (spacing collapses to whitespace) and the inputs ignore `flex:1` so they never stretch to fill the row. `.btn.sm`/`.btn.p` are also undefined (only `.btn.small`/`.btn.tiny` exist), so those 'Add'/'Save'/shortcut buttons fall back to the plain white `.btn` instead of the intended small/primary style.
- **Evidence:** `<div class="row"><input id="mb-name" ... style="...flex:1;min-width:140px"><select ...><button class="btn p" onclick="masterAdd('brands')">Add</button></div>` (line 1362); Grep confirms no `\.row\{`, no `\.btn\.sm\{`, no `\.btn\.p\{`.
- **Impact:** On the Masters and Sync subtabs the add/edit rows lose their intended single-line flex layout: inputs stay at intrinsic width (don't fill), controls wrap on baseline with inconsistent spacing, and 'Add'/'Save' buttons render as plain white (no primary emphasis). Usable but visibly degraded and cramped, most noticeable at 360/412 where the un-stretched inputs waste width.
- **Fix hint:** Add shell CSS: `.row{display:flex;flex-wrap:wrap;gap:8px;align-items:center}` and alias the undefined button modifiers, e.g. `.btn.sm{padding:6px 10px;font-size:12px;border-radius:8px}` and `.btn.p{background:var(--navy);color:#fff;border-color:var(--navy)}` (or change the markup to `btn small`/`btn primary`). Additive only.

## [P2] shell-pastdate-bar-clip-360 — Past-date stepper (#homeDateBar/#todayDateBar) 'Back to today' button can be clipped at 360 — no min-width:0 on valwrap, no ellipsis on .val, main clips overflow-x
- **Module/area:** shell | **Confidence:** medium | **Combo:** 360xMobile
- **Location:** index.html — reflectSelectedDate() lines 2042-2054 (non-flex-wrap row: `‹` + `.valwrap{flex:1}` + `›` + `.btn.small` Back-to-today); `.valwrap` base line 834 (`flex:1`, no min-width:0); `.val` base line 835 (centered, no overflow/ellipsis)
- **Defect:** When viewing a past date, the hero date bar is a non-wrapping flex row (`display:flex` set inline, no flex-wrap) containing two 44px `.rpt-step` arrows (flex:none), a `.valwrap`(flex:1) holding a long `.val` label (`🔒 <date> · viewing past`), and a nowrap 'Back to today' `.btn.small`. `.valwrap` and its `.val` have no `min-width:0`, so the flex item resists shrinking below its content min-width and the row can exceed the hero width at 360; `.val` has no ellipsis so it doesn't truncate. `.main` is `overflow:hidden auto` (horizontal hidden), so the overflow — most likely the right-most 'Back to today' button — is clipped rather than scrollable.
- **Evidence:** `(today?'':'<button class="btn small" ... style="white-space:nowrap">Back to today</button>')` appended to a flex row whose `.valwrap{flex:1}` has no min-width:0; `.main{overflow:hidden auto}` (line 122).
- **Impact:** On a 360-wide phone viewing a previous day, the 'Back to today' escape button (the primary way out of read-only past mode) may be partially cut off on the right edge. The same bar mirrors into #todayDateBar. Needs live confirmation of exact clip point; today-mode (short '📅 Today' label, no extra button) is fine.
- **Fix hint:** Add `min-width:0` to `.valwrap` (and `.val{overflow:hidden;text-overflow:ellipsis;white-space:nowrap}`), or set `flex-wrap:wrap` on the #homeDateBar/#todayDateBar inline style so 'Back to today' drops to a second line instead of clipping. Additive CSS / inline-style tweak only.

## [P3] shell-rep-stick-negmargin-mismatch — Reports sticky header `.rep-stick` negative margins (-16px) don't match `.main` padding (14px mobile / 22px desktop) — edge misalignment
- **Module/area:** shell | **Confidence:** high | **Combo:** all
- **Location:** index.html — `.rep-stick{margin:-16px -16px 12px;padding:14px 16px 10px}` line 863; `.main` padding `14px 14px 18px` line 123, `18px 22px 26px` @≥600 line 705
- **Defect:** The Reports view sticky sub-header uses `margin:-16px` to bleed to the scroller edges, assuming `.main` has 16px horizontal padding. But `.main` padding is 14px on phones and 22px on tablet/desktop, so the bleed over-pulls by 2px on phones (slight clip past the edge) and under-pulls by 6px on desktop (a visible gutter of un-bled cream between the sticky bar and the viewport edge).
- **Evidence:** `.rep-stick{...margin:-16px -16px 12px;padding:14px 16px 10px...}` vs `.main{padding:14px 14px 18px}` / `@media(min-width:600px){.main{padding:18px 22px 26px}}`.
- **Impact:** Cosmetic: the Reports sticky Today/This-month + search + period bar is slightly misaligned to the content edge (2px over on phone, 6px short on desktop). No functional impact.
- **Fix hint:** Match the bleed to the padding: use `margin-left:calc(-1 * var(--main-pad))` via a CSS var, or set `.rep-stick` margins to -14px (mobile) with a `@media(min-width:600px)` override of -22px. Additive only.

## [P3] shell-topbar-crowding-360 — Topbar `.top-actions` (role-select max 140px + 3 icon-btns) is flex-shrink:0 and squeezes brand name to ~70px at 360
- **Module/area:** shell | **Confidence:** medium | **Combo:** 360xMobile
- **Location:** index.html — `.topbar` line 74, `.top-actions{...flex-shrink:0}` line 100, `.role-select{max-width:140px}` line 784, brand `.brand{flex:1;min-width:0}` line 81 (build-badge hidden ≤380 line 1071)
- **Defect:** At 360px the topbar holds the brand (flex:1, min-width:0) plus `.top-actions` which is flex-shrink:0 and contains a role `<select>` up to 140px wide, the UI-mode button, the share button and the admin button (3×38px + gaps). top-actions ≈ 140 + 3×38 + gaps ≈ 270px, leaving only ~72px (minus 16px padding) for the brand. The `<h1>` brand name has ellipsis so it truncates to a few characters, but the store name is effectively unreadable in the topbar on small phones.
- **Evidence:** `.top-actions{display:flex;...flex-shrink:0}`; `.role-select{...max-width:140px}`; `.brand{...flex:1;min-width:0}` with `.brand-meta h1{...white-space:nowrap;overflow:hidden;text-overflow:ellipsis}`.
- **Impact:** Minor: on 360-wide phones the 'Saagar Traders' topbar title is heavily clipped to leave room for the role dropdown and three icon buttons. The Home surface shows the store name separately (.home-store), so no info is truly lost. Needs live check to confirm exact truncation.
- **Fix hint:** Reduce `.role-select` max-width on small phones (e.g. `@media(max-width:400px){.role-select{max-width:96px}}`) or drop the topbar brand text under a small breakpoint (the .home-store already carries it). Additive CSS only.
