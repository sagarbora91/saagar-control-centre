## The flank closed
The daily auto-backup wrote a full-data **plaintext** JSON of ALL business data to the **shared**
`Documents/SaagarBCC-Backups/` folder (up to ~91 files), readable by any file-manager app and surviving uninstall.
Encrypting `bcc.sqlite` (R0-W2) is meaningless while those exist — the contract named R0-W3 a co-requisite.

## What shipped
- **auto-backup.js:** writes to app-private **DATA/** (`var DIR='DATA'`, was `'DOCUMENTS'`); retention `KEEP_DAYS`
  90→7. New `SaagarBackup.readLatest()` (reads DATA `latest.json` → text|null, FS-absent→null, never throws) +
  `SaagarBackup.purgeLegacyDocs()` (deletes ONLY `latest.json` + `/^backup-\d{4}-\d{2}-\d{2}\.json$/` from Documents/ —
  scoped so it can NEVER touch the pre-reset safety backups or archival exports that legitimately share that folder;
  adversarially re-verified).
- **index.html:** `restoreFromDeviceBackup()` (the DATA copy isn't file-picker-reachable, so it reads `latest.json`
  and routes it through the exact existing `handleRestoreFile` validation/preview path via a Blob); gated one-time
  legacy purge in Settings → Data & backup (`runLegacyPurge`/`renderLegacyPurgeRow`, marker `bcc_docs_purged_v1`,
  owner confirms an off-device backup exists first); reworded backup copy + Home nudge to the off-device framing.

## Behavior change (deliberate, not a bug)
The auto-backup **no longer survives uninstall / new-phone** — that role moves entirely to the user-initiated
**Share-to-Drive**, which the reworked nudge escalates. Trades a world-readable full-data dump for an explicit
off-device backup. The dated DATA snapshots (7 kept) are an in-session safety net; only `latest.json` has a restore UI.

## Adversarial (4 skeptics + Opus triage): 0 P0, 2 P1 — folded + re-verified
The purge-scope P0 hypothesis was independently re-verified CLEAR (can only under-delete; the two patterns can't match
`pre-reset-*` / `Saagar_Archive_*` / reports-in-another-folder). Restore path CLEAR (Blob↔File, size guard, rollback-
before-write intact). Both P1s were **device-only-triggerable** (harness has no Capacitor FS → invisible to the harness proof):
- **P1-A:** the off-device nudge read `LAST_BACKUP_KEY`, which a LOCAL "Create backup JSON" (Downloads) and the
  factory-reset safety backup also stamp — so a local export silenced the device-loss guardrail. **Fold:** new
  `OFFDEVICE_BACKUP_KEY` (`st_v2_last_offdevice_backup`) stamped ONLY by `shareBackup`; `backupDays` + the null-state
  nudge now read it; registered like `LAST_BACKUP_KEY` (appControlKeys + restore-validator whitelist). Null-state nudge
  upgraded to red + Share action.
- **P1-B:** the purge marker was set even on partial delete failure → the cleanup row hid forever with files still
  exposed, no retry. **Fold:** mark complete only when `deleted===scanned` (or `scanned===0`); else keep offering + a
  "Removed X of Y — tap again to retry" toast.

## Harness (0 console errors)
API surface + app-private folder string; readLatest/purge browser-safe (null / {deleted:0}); restoreFromDeviceBackup
routes a mocked payload into the Restore-preview modal + builds a review; purge row shows-when-native / hides-when-purged;
fold re-verify: off-device recency ignores local backups + fires at 10 days + key registered; purge marker unset on
partial (2/5, row keeps offering) and set on complete (5/5, row hides). **FS ops (DATA write, latest.json read,
Documents delete) are DEVICE-ONLY.**
